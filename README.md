# Ebb JSON Bot

Небольшой Telegram-бот на JavaScript (ESM) и grammY. Он получает все актуальные типы обновлений Telegram Bot API и отправляет в исходный чат полный объект `Update` как читаемый JSON с отступом в два пробела. Каждая часть JSON показывается внутри `<pre><code class="language-json">…</code></pre>` с Telegram HTML parse mode: символы JSON экранируются, но пользователю виден исходный JSON без HTML- или Markdown-преобразования.

Большой Update делится на несколько сообщений до 4096 символов без потери данных и без разрыва emoji. Бот не повторяет обновления от собственных отправленных сообщений, чтобы не создать зацикливание. Он сохраняет тему forum-чата и Direct Messages канала. Для Guest Mode применяется `answerGuestQuery`: это единственный способ отправить ответ в чат, где гостевой бот не является участником.

Ожидаемые отказы доставки не засоряют журнал: например, если пользователь заблокировал бота или бот был удалён из группы/канала, соответствующая ошибка Telegram подавляется. Неожиданные ошибки Bot API выводятся одной строкой без stack trace, а программные и сетевые ошибки сохраняют полную диагностику.

В личном чате команда `/start` отправляет короткое приветствие с инструкцией и сразу удаляет команду. В группах и каналах у `/start` нет специальной логики: она, как и любое другое входящее событие, отображается в JSON.

В части обновлений Telegram не передаёт ID исходного чата. Если в событии есть пользователь-инициатор (`from` или `user`), например в `inline_query`, `chosen_inline_result`, `shipping_query`, `pre_checkout_query`, `purchased_paid_media`, `poll_answer`, `managed_bot` или `subscription`, бот пытается отправить JSON в личный чат этого пользователя. Для inline-`callback_query` это также запасной вариант, если исходное сообщение недоступно. Пользователь должен уже иметь доступный личный чат с ботом; отказ Telegram (например, если бот заблокирован) обрабатывается без stack trace.

У `poll_answer` анонимного голосования Telegram передаёт `voter_chat`, поэтому JSON отправляется в него. У события `poll` нет ни чата, ни инициатора: бот получает его, но не может определить адресата и выводит понятное предупреждение в консоль. Это ограничение Telegram, а не фильтрация со стороны проекта.

Для реакции, изменений участников, заявок на вступление и бустов бот должен быть администратором чата с соответствующими правами. Чтобы видеть все сообщения в группе, отключите privacy mode у бота в BotFather. Чтобы отправлять JSON в канал, назначьте бота администратором канала с правом публикации.

При запуске long polling grammY обрабатывает все накопленные обновления последовательно. Проект не задаёт начальный `offset` и явно передаёт `drop_pending_updates: false`, поэтому Telegram начинает с самого раннего неподтверждённого Update и очередь не очищается. Telegram хранит необработанные обновления не более 24 часов. Long polling обеспечивает обработку как минимум один раз; после аварийной остановки последние обновления могут быть получены повторно.

## Запуск

Требуется Node.js 20.6 или новее.

```shell
npm install
cp .env.example .env
```

Укажите токен в `.env`:

```dotenv
TELEGRAM_BOT_TOKEN=1234567890:your_real_token
```

После этого запустите бота:

```shell
npm start
```

## Локальный Telegram Bot API

Чтобы направить grammY на локальный сервер Bot API, добавьте его корневой URL без части `/bot<token>`:

```dotenv
TELEGRAM_BOT_API_URL=http://127.0.0.1:8081
```

Если переменная отсутствует или пуста, используется официальный `https://api.telegram.org`.
