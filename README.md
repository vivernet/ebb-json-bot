# Ebb JSON Bot

Telegram-бот на JavaScript (ESM) и grammY. Получает все 27 типов обновлений Telegram Bot API 10.3 и отправляет полный объект `Update` как читаемый JSON с отступом в два пробела. Каждая часть показывается внутри `<pre><code class="language-json">…</code></pre>`: HTML экранируется, пользователю виден исходный JSON.

## Обработка обновлений

Большой JSON делится на сообщения до 4096 кодовых единиц UTF-16 без потери данных и без разрыва суррогатных пар emoji. Бот пропускает сообщения, у которых `from.id` или `sender_business_bot.id` совпадает с его ID. Тема форума, включая личный чат с темами, и Direct Messages канала сохраняется, если Telegram передаёт её в Update. У реакций и событий участников информация о теме может отсутствовать.

Бизнес-сообщения и уведомления об их удалении отправляются через исходный `business_connection_id`. Нажатие пользователем кнопки на сообщении бота отображается как отдельный Update; запрос кнопки подтверждается через `answerCallbackQuery`.

Ответы на временные приватные команды и кнопки (ephemeral) остаются видимыми только их инициатору. Если Telegram не передал данные для такого ответа, бот выводит предупреждение и не отправляет JSON в общий чат. Доставка ephemeral-ответов зависит от короткого окна Telegram и прав бота.

В личном чате новое обычное сообщение с `/start` получает приветствие с инструкцией. После успешного ответа бот удаляет команду; уже удалённая команда не вызывает ошибку обработки. В группах, каналах, бизнес-сообщениях и редактированиях `/start` отображается как JSON.

## Guest Mode

Для гостевого режима применяется `answerGuestQuery`: боту не нужно состоять в чате. JSON до 4096 кодовых единиц отправляется обычным HTML-блоком; более длинный — одним rich-блоком кода с языком `json`, до 32768 символов Unicode. При необходимости убираются только отступы JSON. Если даже компактный JSON не помещается, бот объясняет ограничение вместо отправки обрезанных данных.

## События без исходного чата

Если Telegram передаёт только пользователя-инициатора, бот пытается отправить JSON ему в личный чат. Это применяется к `inline_query`, `chosen_inline_result`, `shipping_query`, `pre_checkout_query`, `purchased_paid_media`, `poll_answer`, `managed_bot`, `subscription` и `callback_query` без исходного чата. Пользователь должен уже иметь доступный личный чат с ботом.

У `business_connection` используется `user_chat_id` владельца подключения. Если пользователь голосует от имени чата, `poll_answer.voter_chat` становится адресатом. У события `poll` нет ни чата, ни инициатора: бот выводит предупреждение. Неизвестный тип Update без распознаваемого адресата также получает предупреждение.

## Доставка и журнал

Ожидаемые отказы доставки, например блокировка бота или удаление из группы, не засоряют журнал. Неожиданные ошибки Bot API выводятся кратко; программные и сетевые ошибки сохраняют стек и причины. Токен бота скрывается в диагностике, параметры запросов целиком не выводятся.

При отказе Telegram с `retry_after` официальный модуль `@grammyjs/auto-retry` повторяет запрос не более трёх раз с ожиданием до 60 секунд за один отказ. Успешно отправленные части JSON не повторяются. Сетевые ошибки и ошибки сервера не повторяются автоматически: после них результат отправки может быть неизвестен. При исчерпании повторов ошибка записывается в журнал; постоянной очереди повторной доставки в проекте нет.

Long polling обрабатывает накопленные обновления последовательно. Проект не задаёт начальный `offset` и передаёт `drop_pending_updates: false`, поэтому очередь Telegram не очищается. Telegram хранит обновления не более 24 часов; после аварийной остановки возможны повторы. Подтверждение Update не является гарантией успешной отправки JSON: ошибки обработчика логируются, после чего polling продолжается.

`SIGINT` и `SIGTERM` запускают одну остановку с ожиданием обработки текущего обновления и подтверждения offset. Ошибки запуска или остановки завершают процесс с кодом 1.

## Запуск

Требуется Node.js 22.9 или новее; рекомендуется Node.js 24 LTS, указанный в `.nvmrc`. Node.js 20 больше не поддерживается проектом.

```shell
npm ci
```

Скопируйте `.env.example` в `.env` (`Copy-Item .env.example .env` в PowerShell или `cp .env.example .env` в Linux/macOS), затем укажите токен:

```dotenv
TELEGRAM_BOT_TOKEN=1234567890:your_real_token
```

```shell
npm start
```

На сервере переменные можно передать через окружение без файла `.env`. Уже заданные переменные окружения имеют приоритет. Не запускайте два процесса polling с одним токеном одновременно.

Для реакции, изменений участников, заявок на вступление и бустов нужны соответствующие права администратора. Для получения всех обычных сообщений группы отключите privacy mode в BotFather или назначьте бота администратором. Для отправки в канал требуется право публикации. Бот показывает полный Update участникам чата, включая доступные ему служебные поля; используйте его там, где такой диагностический вывод уместен.

## Локальный Telegram Bot API

Укажите корневой URL сервера, поддерживающего Bot API 10.3, без `/bot<token>`, логина, пароля, query-параметров и фрагмента:

```dotenv
TELEGRAM_BOT_API_URL=http://127.0.0.1:8081
```

Префикс пути обратного прокси разрешён. Если переменная отсутствует или пуста, используется `https://api.telegram.org`.

## Структура и проверки

- `src/index.js` — запуск и итоговая диагностика процесса.
- `src/config.js` — загрузка и проверка настроек без побочных эффектов при импорте.
- `src/polling.js` — параметры очереди и корректная остановка.
- `src/bot.js` — обработчики, отправка, повторы и классификация отказов.
- `src/update-target.js` — адресат, темы, business и ephemeral-контекст.
- `src/update-json.js` — сериализация, HTML и разбиение UTF-16.
- `src/guest.js` — ответ Guest Mode с учётом лимитов.
- `src/errors.js` — безопасная диагностика без токена.
- `src/update-types.js` — явный список Update, сверяемый тестом с grammY.

```shell
npm test
npm run check
npm audit
npm outdated
```

Тесты используют фиктивные обновления и транспорт, не читают `.env` и не отправляют сообщения в Telegram. `check` проверяет синтаксис всех JavaScript-файлов в `src`, `test` и `scripts` без их запуска.

Контракты: [Telegram Bot API](https://core.telegram.org/bots/api), [повторы запросов grammY](https://grammy.dev/plugins/auto-retry), [версии Node.js](https://nodejs.org/en/about/previous-releases).
